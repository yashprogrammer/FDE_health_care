1. Introduction

1.1 Purpose & scope

This document describes the design of the CityCare Discharge Copilot, an AI-assisted discharge-summary system added to CityCare Hospitals' 2011-era Hospital Management System, MediTrack HMS v3.2. It covers three stages:

2. Business context

2.1 The in-patient discharge cycle

Every admitted patient passes through the cycle below. For cashless (insured) patients, the hospital cannot release the patient until the insurer, via the TPA, approves the final bill. That approval requires a complete discharge summary and supporting documents.

2.2 Problem statement

Stated problem (CEO): "Doctors are drowning in paperwork. Build us a ChatGPT for discharge summaries."
Real problem (from data): Insured patients wait ~6.3 hours to go home after discharge is advised (vs ~2.5 h for cash patients) because discharge summaries are slow to write and often incomplete for insurers: 38% of TPA submissions come back with a query. This blocks beds and is the top patient complaint.

4. POC: High-Level Design

4.1 Objectives & non-goals

Objectives

  • Prove an LLM can draft discharge-summary narrative without inventing facts
  • Measure quality against doctors' own summaries (evals)
  • Prove latency and cost are acceptable
  • Get clinician and TPA-desk feedback (business verification)
  • Validate the TPA-readiness rules against real query reasons

Non-goals

  • No connection to MediTrack or any live hospital system
  • No identifiable patient data (de-identified export only)
  • No signing, write-back, or production hardening
  • No UI polish; Streamlit is deliberately throwaway

4.2 Architecture

4.3 What the AI writes vs what is deterministic

Summary sectionProduced byRationale
Final diagnosis + ICD-10MediTrack dataLegal and insurance fact; already coded
Discharge medicationsPharmacy dataA hallucinated drug or dose is a patient-safety event
Reports pending at dischargeLab dataFrequent TPA query when omitted
TPA-readiness checklistRules engineInsurer rules are known, so code them
Presenting complaints, hospital course, procedure findings, key investigations, condition at discharge, follow-up, diet & activityLLM draftTurning scattered free-text notes into a coherent narrative is where LLMs add value. Always doctor-editable.
Design principle: the best AI solution here is roughly 30% AI and 70% deterministic engineering. The LLM is used only where no source of truth exists.

4.4 Technology stack

ConcernChoiceWhy
UIStreamlit 1.64Fast to build, disposable, familiar to data teams
Agent frameworkPydantic AI 2.50Typed, validated structured output; native Logfire instrumentation
Modelgroq:openai/gpt-oss-20bOpen-weight, very fast on Groq, low cost
Structured outputNativeOutput(SummaryDraft)Provider-enforced JSON schema (Groq rejects gpt-oss tool-call output)
ObservabilityLogfire (OpenTelemetry)Prompt, output, tokens, latency per run
DataJSON export; pandas for eval tablesNo database needed

4.5 Evaluation strategy

Each of the 11 historic encounters is drafted by the AI and scored automatically against the patient's source data and the doctor's original summary. Clinicians and the TPA desk then score a sample by hand (Clinician feedback tab). Automatic metrics are defined in 5.7.

5.4 Agent configuration

SettingValue
Modelgroq:openai/gpt-oss-20b (env COPILOT_MODEL)
OutputNativeOutput(SummaryDraft): JSON schema enforced by the provider; list fields default to empty so partial outputs are not rejected
Model settingsmax_tokens=6000, temperature=0.2, groq_reasoning_effort="low" (caps reasoning so it cannot exhaust the budget)
RetriesAgent validation retries = 2; plus 2 attempts around provider errors (HTTP 400 schema rejections are not retried by the framework)
Pricing (config)USD 0.075 / 1M input tokens, 0.30 / 1M output tokens; INR at 88/USD

Prompt rules (INSTRUCTIONS)

  • Use ONLY facts in the encounter data; never invent drugs, doses, lab values, dates, diagnoses or procedures.
  • Copy numbers exactly (values, units, LVEF, stent sizes). Dates as DD/MM/YYYY; never predict a discharge date.
  • Do not write a discharge medication list (added from pharmacy). Mention PENDING reports as awaited.
  • Hospital course: 4–7 chronological bullets in Indian clinical style (CAG, PTCA, DES, LVEF, TIMI allowed).
  • List every procedure. Follow-up / diet only if stated; otherwise "As advised by treating consultant". Fill every schema field.

5.9 De-identified export

poc/export_deidentified.py opens MediTrack read-only (mode=ro), selects discharged admissions that have a typed summary, builds each Encounter, then applies deidentify(): IP No → ENC-nn, name → Patient ENC-nn, UHID → SHA-256 prefix, policy → XXXX. Clinical content is preserved.
